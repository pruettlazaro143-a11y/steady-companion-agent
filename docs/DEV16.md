## A：明确活动与有限对象引用

`interaction-scope-v3` 仍先解释整段表达，再一次提交状态。已支持的“帮我写/起草/改写/润色/翻译……”“把……改成/改为/缩成/压缩成……”等形式直接判为文字任务，不需要把宾语加入领域词典。每个新对象用 OI 序号、真实消息 I 编号及字符 span 表示，限定 `requested_text_only`；不推断主题或用户特征。明确代词改写可以沿用当前对象，否则绑定新的原话范围。没有可支持的对象/活动时输出 unknown，不用“识别成功”填补。

对象原话只在用户数据消息中送入生成器；system 只含编号、范围、枚举和偏移。引用须来自当前会话的实际用户消息。来源被 clear/revision 失效清除时，任务对象同时失效；边界不会因此被自动解除。对象不是长期记忆，不生成新用户事实。

“别问我以前的经历”“我的过去就别再问了”形成 `personal_history` 限制，不取消当前文字任务，也不禁止与交付物有关的澄清。“先不谈这个，也先不分析”分别保存当前会话对象和 analysis 边界。只撤回分析不撤回独立写作，整项邀请的后续撤回则不允许先打开权限再补救。明确恢复只解除对应边界；解除过去经历限制本身不是全面个人分析授权。

新增任意有限名称的暂停形式：若名称逐字存在于当前任务原话，可关闭当前任务线程；否则保留有真实来源的 `unresolved_named_object` 边界，由既有窄检查处理与当前回复的关系，不声称已解析该关系。恢复新任务不会批量删除无关边界。旧主题词表仍用于兼容检索/已有分析路径，并非本版文字任务的前置条件。

解释仍受限制：控制输入解析超过 1200 字符时标 `input_limit_unknown`；未配对引号、转述、条件、复杂否定或不支持形式可保持 unknown/partly_unknown，不得扩大权限。反讽、任意指代、隐含邀请、任意跨句否定尚未解决。没有新增付费语义解释器，没有声称正则实现了通用理解。

个人习惯预设的问句增加选择性触发信号，不依赖问号，也不自动判违规。真实邀请、虚构人物或合法任务澄清仍由同一次窄检查结合原话判断。边界存在时沿原机制触发检查，可能增加实际检查次数，但每轮仍最多一次；生成、检查和已有获授权辅助共享原总预算。无新增审阅层、无失败重生成。

## B：范围内如何参与，只是可验证装载的指导

日常 profile 改为 `companion-v3`，v1/v2 文件逐字节保留，Nebius checked 路径不变。完整 core/R-A/safety 保留；供应商、模型、采样、思考、格式及调用上限不改。

指导区分分享、共同创作、明确要求列方案、受挫、具体交付、收窄与暂停。新合成对照包含旧钥匙太空驿站、纸偶布展、折纸演示等独立语境，演示相邻轮的邀请变化，不使用实际模型输出，不作为标准答案。当前示范与真实 user/assistant 历史分开承载，不计入用户事实或记忆提取。没有固定句数、问题数、禁用列表或固定结尾要求。

示范总长仍小于既有 3000 字符上限，生成指导小于 6000 字符。额外输入文字可能影响 token 和等待，但未实测，不把字符量写成 token 或效果收益。实际指导长度和哈希见离线证据与材料 manifest。

## C：来源关系不等于事实

`dialogue-source-relations-v1` 每个请求从真实最近历史和本次输入派生，最多 12 条角色引用；不持久保存、不新建第二份历史。助手文本始终是 `assistant_contribution_not_user_evidence`，用户文本也不自动成为现实事实。仅“就用/采用/保留/选定 + 明确引用片段”且有唯一助手原文来源时，建立当前任务内的片段采纳关系；疑问、撤回、不确定、重复来源或含糊认可保持 unresolved。采纳一个片段不扩到其他对象，也不等于用户生平或事实查证。

该表置于不可信上下文，不进入自动记忆输入。存储仍只接受原有获授权用户来源；实际 auto 模式回归检查了“助手创意→用户采用虚构设定”没有写入用户事实，并以真实用户普通偏好作可保存对照。不为这一轮扩大保存范围，也不自动开启辅助。

并未实现完整语义的创作世界状态机。未命中的明确采纳可能仍依赖模型阅读原话；来源标记、指导及引用关系都不能保证模型不再混淆设定。此限制与规则已覆盖的权限路径分别报告。
