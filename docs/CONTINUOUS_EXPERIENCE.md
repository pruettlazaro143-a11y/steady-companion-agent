# 连续陪伴体验 · dev15

基于公开 dev14 `253bcfee175f76b68d768960d44e66a79425c044`。本入口观察普通交流、共同创作、受挫、具体求助、收窄范围与暂停如何接续。不是模型横评，也不把短回复、少问题或检查通过当作陪伴质量。

## 只需启动一次

在解压的 **dev15 源码根目录**、Python 3.10+ 环境运行下列命令。`--confirm-live` 明确授权本次收费请求和本地合成可见文本记录；实施阶段未执行此命令。

```sh
python3 -m steady_companion eval-experience --connection ./configs/deepseek-official.json --interaction-control session --interaction-check selective --confirm-live
```

沿用 DeepSeek 官方 `deepseek-flash`、关闭思考、服务默认采样、companion-v1。凭据通过终端隐藏输入或本机独立的 STEADY_DEEPSEEK_API_KEY 提供；不回退 Nebius。无需连接探测。只去掉 `--confirm-live` 就是完全离线的脚本预览，既不读凭据也不打开数据库。需要固定报告位置时，加 `--output ./eval-results/my-continuous-dev15-01`；整个目录必须不存在，已存在即停止，发生在读密钥之前。

本入口固定开启 **session / selective**，正式 chat 的默认开关不变。最多 **6 个用户轮、12 次总请求**；每轮一次生成，触发时再检查一次，所有失败请求也计数。无自动重试、修复重生成、模型切换、预算扩张、摘要、记忆辅助或 /learn。使用新临时合成库，manual；正常结束、拦截及可处理异常后清理临时库，不接触默认或 `--data-dir` 指向的原用户库。操作系统强杀/断电不能保证清理完成。

## 固定的新写合成情境

1. 喜欢给虚构城市画散步地图，画了一条只在下雨时营业的街。
2. 顺着实际前答，为这条街共同构思一家小店。
3. 讲社团展示地图时练过却漏讲喜爱的小路，有点失落，暂不请求分析。
4. 明确请稳伴写约三十秒的地图介绍开场。
5. 只讨论这次开头、不追问过去，改成两句可以直接说的话。
6. 累了，暂停当前话题和分析。

完整原文由离线预览或 `steady_companion/experience_eval.py` 中 SCENARIO 提供。没有预置助手台词；后续请求仅含实际交付前文。第 2–6 轮前，终端显示实际前答和下一条用户脚本，**确实适用才输入 y**。不适用、无法确认或 EOF 就记录 not_applicable 并停止；Ctrl-C 记录取消。不改写脚本迎合回复，不填补助手历史，不另开替代轮。确认不是自然度评分，不作为模型输入，确认时输入的任意原文不落报告。

检查 conflict、unknown、技术失败、预算不足均停止；保留原结果，不显示未通过的候选。selective 没触发明确写 not_triggered，绝不记为 pass。没有把检查器判 conflict 当作已经证明生成内容有问题。

## 本地报告

启动时打印唯一目录 `eval-results/continuous-dev15-日期-随机标识/`，含：

- `events.jsonl`：脚本与版本/材料哈希、每次请求的开始和结果、每轮输入、实际交付回复、单独的未交付候选、检查状态及合法结果、阶段耗时、各次服务用量、累计 Usage、结束原因及未完成项。
- `report.md`：同一组过滤后数据的可读版本。将整个目录交给设计侧即可；程序不会上传或调用 GitHub。

请求开始记录先落盘，避免中断后误称未调用。生成/检查的耗时是本机测到的传输调用时长，轮次 diagnostics 另记录宿主流程时长。服务未返回用量时保留 null 和 unreported_calls；不推算收费为零。若进程被强杀，可能只有 request_started，没有最终用量，不能凭此补写结果。

仅本次明确合成评测捕获可见文本，包含被拦截候选；与 delivered_reply 分字段保存。隐藏推理、分析标签、凭据、请求头和任意异常原文不保存。可见内容无法通过已有过滤时整段省略；不会从混合推理内容中猜出回复。文件权限为当前用户读写，新报告目录仅当前用户访问。普通私聊不因新增入口开启全文日志。

报告的 human_review 是人工审阅栏位，不是自动评分，需分别判断：**生成内容本身的问题、合理内容被误拦的可能、技术失败、完成交流后的自然度与帮助质量**。允许同时存在多种情况。completed_pending_human_review 只表示六轮交付完成。检查器的真实识别能力仍未验证。

## 费用依据与未知项

上限是 6 次生成 × 4096 输出 tokens + 6 次检查 × 1200 输出 tokens，即 **31,776 个请求配置上的输出 token 上限**；生成超时 90 秒，检查 20 秒。实际请求可能少于 12 次。该数字不是费用，也不含输入 tokens。

金额未知：输入长度/服务分词、缓存命中、账户当前费率和失败调用收费均未由宿主确定。金额需按服务实际输入（含缓存分类）与输出用量分别乘对应费率计算。本入口没有货币硬上限，未提供或记录金额时一律 unknown，不能把请求数换算成金额。没有为估价新增收费探测。

## 离线与兼容边界

程序测试使用新合成响应和模拟传输，仅验证连续历史、范围交付、预算、报告和失败处理；不证明真实回答自然或检查准确。不改 engine、InteractionState、检查合同、模型接入、core/R-A、安全规则或用户记忆模式。旧 dev14 标签与交付保留，日常和 Nebius 原入口仍可用。独立 Skill 同步版本，并不包含此评测执行器。

GitHub CI 账号限制单独记录；本地测试通过不写成云端通过。本地体验目录不纳入公开 manifest 或 Release。实现阶段真实模型调用 0 次，用户本机启动后才能获得新的效果证据。
